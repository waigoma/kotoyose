# kotoyose-delegation

Kotoyose の MCP サーバー `kotoyose` が使えるとき、自分とは別の alias に作業を頼めます。
alias は、model・prompt・道具・実行場所をまとめた作業環境の名前です。
別の会社の model、別のサブスクの枠、別の得意分野を使えます。

## 道具

- `list_agents()`: 頼める alias の一覧を返します。各項目は `alias`・`description`・`model`・`place` です。
- `ask_agent(alias, task, conversation_id?)`: `alias` に `task` を 1 回頼み、`text` と `conversation_id` と使用量を返します。
  - 同じ相手に続きを頼むときは、前回の `conversation_id` を渡します。
  - 渡さなければ、新しい会話として始まります。

## 頼む前に

1. **まず `list_agents` を呼ぶ。** 一覧は呼び出し元の権限で絞られています。一覧に無い alias は頼めません。alias の名前を推測しないでください。
2. **`description` で選ぶ。** 用途が合う alias を選びます。迷ったら、速くて安い alias に先に頼み、足りなければ強い alias に頼みます。
3. **頼むほどの仕事か考える。** 次の場合は、自分でやります。
   - 数行で答えられる質問
   - 自分の会話の流れ全体を知らないと判断できない仕事
   - 同じファイルを今まさに自分が編集している仕事 (相手は別の場所で動くので、同時に編集できません)

## 依頼文 (`task`) の書き方

相手には、**`task` の文章だけ**が渡ります。自分の会話の履歴、読んだファイル、決めたことは渡りません。

- それだけ読めば仕事ができるように書きます。目的、前提、範囲、終わりの条件、返してほしい形を入れます。
- 必要な事実や本文は、`task` の中に書き写します。「さっきのファイル」のような参照は通じません。
- 返してほしい形を指定します (例: 「結論を 3 行、次に根拠を箇条書きで」)。
- **秘密を入れません。** API キー、パスワード、token、個人情報は書かないでください。

## 返ってきたものの扱い

- 返事は、相手の model の意見や作業の結果です。そのまま正しいとは限りません。大事な事実は、自分で確かめてから使います。
- 返事を利用者に伝えるときは、どの alias に頼んだかを添えます。
- 足りなければ、同じ `conversation_id` で追加の指示を出します。最初からやり直すより安く済みます。

## 制限

- 頼まれた側 (子) は、さらに別の alias に頼めません (孫は作れません)。
- 同時に頼めるのは 4 件まで、1 時間に 32 件までです。並べて頼むと速く終わりますが、各社の利用枠も同時に使います。
- 時間の上限は、頼んだ alias の設定に従います。長い仕事は小さく分けて頼みます。
- 自分の turn を取り消すと、頼んだ仕事も止まります。
